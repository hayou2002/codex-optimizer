# 结构与会话

## 默认根

默认治理根是 `~/Desktop/OH-WorkSpace`，可在 `.optimize/codex-rules.json` 中改为其他绝对路径。它同时是 Hanako 与 Codex 的共享工作根。默认根承载：

- `projects/`：长期项目，主编辑位。
- `storage/docs/`：跨项目长期文档。
- `storage/backups/`：需要保留的备份。
- `storage/tools/`：跨项目工具。
- `inbox/`：暂时不能安全分类的少量文件。
- `_temp/`：有生命周期的临时物、计划、报告、检查点和回收区。
- `.optimize/`：Codex optimize 的现场规则。
- `YYYY-MM-DD/<任务>/`：Codex 为 projectless 会话生成的工作目录。

目录结构格本身即使为空也不判为空目录垃圾。

## Codex 日期目录的存储含义

Codex 会话记录保存在 `$CODEX_HOME/sessions`，会话元数据保存首次工作目录 `cwd`。projectless 会话的生成目录通常形如 `OH-WorkSpace/YYYY-MM-DD/<slug>`；同名时可能追加 `-2`、`-3`。这个目录是执行与文件定位路径，不是聊天记录本身。

因此：

- 原目录被移动后，历史聊天通常仍在，但旧 `cwd` 中的命令、相对路径和文件检查可能失效。
- 不因目录很老直接搬走或删除。
- 项目化优先复制实际使用和可交付文件，再通过 `source.md` 建立来源。
- 只有完整迁移条件成立后，旧日期任务目录才进入回收区。

Codex 没有为生成目录命名算法或自动回收提供公开保证，执行时以现场路径、会话元数据和实际引用为准。

## 落点规则

| 对象 | 去向 |
|---|---|
| 某项目的源文件、工作文件、交付物 | 当前 `projects/<slug>/` |
| 项目运行产生的中间文件 | 项目的 `work/` |
| 项目最终交付物 | 项目的 `outputs/` |
| 跨项目长期文档、工具或备份 | 默认根的 `storage/` |
| 有寿命的截图、导出、调查文件、会话中间物 | 默认根的 `_temp/` 对应格 |
| 无法判断归属的少量内容 | `inbox/` |
| 普通 projectless 会话产物 | 当前日期任务目录，直到项目化 |

不把普通个人资料、认证或运行数据库塞入项目或 `storage`。

## 已添加项目

已添加项目来自 Codex 原生项目列表。运行时动态读取，不通过扫描磁盘猜测。项目工作根可以是默认根之外的位置，并共享默认根的规则、计划、回收区和检查点。`OH-WorkSpace/projects/` 是 Hanako 与 Codex 的共享项目位；每个 Agent 仍保留自己的 checkout 和私有状态。

- 新建项目：加入 Codex 项目列表。
- 项目路径变化：报告旧登记，不自动猜新路径。
- 项目移除：停止自动治理该位置，下一次运行提示清理旧登记。
- 外部路径缺失：只报告，不删除登记。

## 项目骨架

```text
projects/<slug>/
├── README.md
├── source.md
├── AGENTS.md             # 简短项目入口与边界
├── work/                 # 有工作文件时创建
└── outputs/              # 有交付物时创建
```

`README.md` 写目标、当前状态和入口；`source.md` 写来源与迁移方式；项目 `AGENTS.md` 只写入口、目录纪律、验证和边界。`work/checkpoints/`、`work/conflicts/` 等在真实需要时创建，不预建空目录。

## 日期目录与项目关系

- 项目建立后，项目是唯一主编辑位。
- 日期目录是历史快照，不回写。
- 同一项目的新工作直接写项目，不再写新日期副本。
- 日期目录只有在来源映射、未迁移内容和恢复副本检查通过后才可以整目录软删。
