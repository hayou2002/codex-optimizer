# 项目迁移

## 何时建立项目

以下任一条件可触发：

- 用户明确说“这是项目”“以后继续用”或指定 `projects/<slug>`。
- 同一逻辑项目跨日期或多次出现，组合身份至少两项一致，综合评分达到 6 分。
- 用户选择“整理”且当前会话已产生持续维护价值。

用户显式项目不受跨日期门槛限制。

## 快速归位

已知一个具体源目录或 Git URL，并且用户明确把它作为项目时，直接进入快速路径：

```powershell
$cli = "$env:USERPROFILE\.codex\skills\codex-optimizer\scripts\codex_optimizer.py"
python $cli quick-project --root "$env:USERPROFILE\Desktop\OH-WorkSpace" `
  --source "D:\path\to\project" --slug "example"
python $cli quick-project --root "$env:USERPROFILE\Desktop\OH-WorkSpace" `
  --git-url "https://github.com/example/project.git" --slug "example"
```

快速路径只做以下工作：

1. 确认目标 `projects/<slug>` 不存在。
2. 克隆 Git 仓库，或复制本地项目；`--move` 仅在用户明确要求搬走源目录时使用。
3. 跳过常见缓存、凭据、密钥和数据库文件。
4. 缺少时补一个简短 `README.md` 和 `source.md`；保留已有文件。
5. 返回目标路径、来源和跳过项，结束。

它不扫描整个工作区，不写双份检查点，也不为单 Agent 创建租约。普通复制不逐文件计算 SHA256，也不另做第二份备份。不预建空的 `work/` 或 `outputs/`。

目标已存在时停止。需要合并、覆盖、删除来源或处理冲突时，才转入完整计划与回滚流程。

## 组合身份

为候选项目收集：

- 语义 slug、README/项目说明、项目级 AGENTS。
- git remote、仓库根与 manifest。
- 会话中的实际文件读写路径。
- 文本文件内容 hash 或目录文件集合相似度。
- 日期目录与既有关联项目。

只有单一目录名相同不足以合并。无法确认时保留候选和来源目录。

## 默认评分

| 信号 | 分 |
|---|---:|
| 用户明确说项目、长期维护或以后还要用 | 5 |
| 两个以上可交付成果，或包含唯一源 | 3 |
| 后续会话还要引用、更新或继续执行 | 2 |
| 正式文档、代码仓库、脚本工具链或外部引用 | 2 |
| 跨日期/多次出现 | 2 |

普通问答、一次性调查、单个导出、缓存和完全生成状态不计分成可交付成果。默认 `projectPromotion.scoreThreshold=6`；跨日期/多次阈值为 2 个日期或独立出现项。显式项目声明跳过阈值。

## 哪些文件进入项目

以会话实际读取、写入、执行和产出的路径为准，加入正式文档、源文件、脚本、配置模板、最终交付物和必要资产。

排除：

- `.git`、缓存、构建环境、`node_modules`、`.venv`
- 日志、临时文件、编辑器状态
- `.env`、密钥、token
- 数据库、WAL/SHM 和运行态数据
- 会话原始 JSONL 与 Codex 主目录状态

大资产可全部复制；一批不因单批大小被拆开。全部复制并校验成功前不删除任何来源。

## 当前可用版本

不是每个历史版本都保留。优先：

1. 已存在项目中的当前版本。
2. 用户明确指定或本会话实际在用的版本。
3. 能验证完整、可读和可执行的有效版本。

相同文件集合且大小一致时直接跳过并记录来源；需要确认同名内容是否相同时再比较内容或 hash。同名不同内容时：

- 能确认当前可用版本时，以项目版本或用户明确版本为准。
- 不能确认时写入 `work/conflicts/<source-slug>/`，两份保留，原日期目录不软删。

不单凭 mtime 覆盖项目文件。

## 复制与验证

1. 先用一次 `organize-scan` 盘点；只对仍有维护价值的项目生成可读方案。
2. 目标使用语义 slug，冲突追加 `-2`、`-3`。
3. 按需创建简洁的 `README.md`、`source.md`；共享、持续协作或复杂项目确有需要时再创建项目 `AGENTS.md`。不为全部历史项目批量补文档。
4. 按需创建 `work/` 和 `outputs/`。
5. 写入文件时使用临时文件加原子替换。
6. 核对目标文件存在且大小一致；只有跨盘后删源、同名冲突或发布包完整性才校验 SHA256。
7. 动作完成后只做一次验收：核对 transaction、动作数量、源/目标存在性，以及仍在使用的入口或源文件。

## 过程数据隔离

`organize-scan` 默认查看项目根和常见过程目录，最多 4 层、400 个条目；
达到预算只标记 `truncated`，不继续深挖。需要针对某个项目完整审计时再单独
扩大范围。

项目里的浏览器 profile、登录/运行数据库、缓存和临时过程产物不视为项目素材，
也不走低风险自动清理。一次确认来源、目标、风险和恢复位置后，整组移入项目内
`_temp/trash/<batch>` 或治理根恢复区，坏路径和占用项跳过。运行态数据只保留，
不自动硬删。

## 关联同步

路径只是换位置且没有旧路径引用时，不触发记忆、经验、Git 和配置更新。确实命中
旧路径时，只更新 `AGENTS.md`、项目入口、rules 和自动化中的相关位置。只有项目
身份、仓库或挂载关系变化时才处理 Git tag、偏好和挂载配置。不要为普通整理固定
执行十步同步。

## source.md

至少记录：

- 项目 slug 和建立时间
- 来源日期目录绝对路径
- 关联会话 ID
- 首批复制文件、数量与验证依据
- 后续加入来源和加入时间
- 排除对象与原因
- 日期目录迁移状态

任何后续日期目录只有出现来源记录或用户明确关联，才算同一个已迁移项目。

## 日期目录软删条件

同时满足才可移入回收区：

1. 来源映射存在，目标项目有效。
2. 所有实际使用和可交付文件都已复制，并按动作风险核对大小或 SHA256。
3. 日期目录没有未迁移唯一源、凭据或运行态必需内容。
4. 关键面没有仍依赖旧路径的引用，或引用已修复并验证。

不附加“必须超过 N 天”条件；刚完成迁移也可软删，但仍有 14 天恢复期。任一条件不满足就先报告。

## 项目后续

项目建立后：

- 新工作直接写项目。
- 日期目录保持历史源，不回写。
- 同项目再出现在日期目录时，按实际在用文件增量补入项目。
- 快速归位由 `source.md` 记录。安全清理或实际协作后只写一条简明检查点，不再默认同时写项目和全局两份。
